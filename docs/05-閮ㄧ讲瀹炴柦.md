# V2.0 私有化部署与实施

## 1. 参考配置

针对 1–20 台 CNC、20–50 名员工的初始规模，可从 4–8 vCPU、16GB RAM、500GB 企业级 SSD 起步，并按设备采样频率、影像/图纸数量、保留周期调整。建议配置独立备份目标、UPS、NTP、监控与受控管理网段。实际容量应通过采样点数、频率、保留天数和并发用户数进行估算。

## 2. 启动步骤

```bash
cp .env.example .env
# 修改数据库密码、TOKEN_SECRET、MES_ADMIN_PASSWORD
# DATABASE_URL 中的密码必须与 POSTGRES_PASSWORD 一致
docker compose up --build -d
docker compose ps
curl http://localhost:8000/health
```

API 启动前执行 `backend/migrate.py`：
- 新环境：Alembic 依次创建 V1 基线和 V2 表。
- 已有 V1 环境：识别 `work_orders` 且无 `alembic_version` 时打标 V1 基线，然后创建 V2 表。
- 迁移完成后 FastAPI 启动并按环境变量初始化管理员账号。

前端地址 `http://localhost:5173`，API 文档 `http://localhost:8000/docs`。若从其他客户端通过服务器IP访问，需在 `.env` 设置 `CORS_ORIGINS` 为相应前端来源，例如 `http://192.168.1.50:5173`。

## 3. 备份与恢复

```bash
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB"' > backup.sql
```

恢复前停止 MES 写入，使用隔离数据库执行恢复并核对记录数、工单、报工、库存、检验、NCR、排程和审计后再切换。定期演练恢复，不以“备份命令成功”替代恢复测试。

## 4. OT/IT网络安全

MES 不直接向 CNC/PLC 发送控制命令。设备网关置于 OT/IT DMZ 或隔离采集区，防火墙仅允许必要的数据采集方向、协议和端口。设备驱动应采用只读账号/只读点位访问。程序下发、PLC写控制、远程启动/停止必须作为独立高风险变更评审，不能通过本项目当前接口实现。

## 5. 建议实施阶段

1. 现场调研机床品牌、控制器型号、通信选件、点位清单和工艺约束。
2. 清洗工单、产品、图纸、工艺、员工、机床、刀具和物料主数据。
3. 选择一个产品族配置工艺路线，核对标准节拍、准备时间和质量规范。
4. 一台 CNC 只读联网试点，验证设备时间戳、质量码、断线缓存与数据去重。
5. 一个班组并行试运行，核对生产报工、NCR、排程审批和产量口径。
6. ERP 工单入站先做字段映射和对账，再单独设计完工回传、幂等和失败重试。
7. 权限、备份、恢复、监控、培训和切换审批完成后，分批上线。

## 6. 投产前关口

必须完成：企业SSO/MFA或经批准的身份方案、V1逐接口角色授权、Token密钥管理、HTTPS、数据库权限最小化、Alembic迁移演练、备份恢复、设备协议联调、数据保留、容量/性能测试、质量处置授权、工艺冻结与现场签字验收。未完成这些关口前，V2.0定位为可验证的工程MVP，不是已认证的生产MES。
