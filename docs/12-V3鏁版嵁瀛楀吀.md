# V3.0 数据字典

V3.0 复用 V2 的 `device_readings` 时序表，并扩展以下 MES PostgreSQL 表。边缘网关本地 Outbox 是独立 SQLite 数据库，不进入 MES PostgreSQL。

| 表 | 关键字段 | 说明 |
|---|---|---|
| `edge_messages` | `message_id`, `machine_id`, `payload_hash`, `received_at`, `source` | 全局唯一边缘消息ID及payload摘要；相同ID相同内容幂等，内容不同返回409 |
| `machine_state_periods` | `machine_id`, `state`, `started_at`, `ended_at`, `reason`, `source`, `event_id` | 将状态变化保存为时间段；当前状态 `ended_at` 为空 |
| `edge_gateway_heartbeats` | `gateway_id`, `status`, `version`, `ip_address`, `last_seen_at` | 网关心跳；90秒以上未更新在查询结果中标记 stale |
| `alarm_rules` | `rule_code`, `machine_code`, `point_name`, `operator`, `threshold`, `severity`, `cooldown_seconds`, `enabled` | 数值点位阈值规则，可指定单设备或全设备 |
| `alarm_events` | `event_key`, `machine_id`, `rule_id`, `severity`, `status`, `acknowledged_by`, `resolved_by` | 报警实例，支持确认与关闭，写操作记录 V2 `audit_logs` |

## 复用的 device_readings 字段

- `machine_id`：对应 V1 `machines.id`。
- `point_name`：标准点位代码，如 `spindle_load_pct`、`good_count_total`。
- `numeric_value` / `text_value`：按数值/文本分列。
- `quality`：采集质量码；OEE 计数器及阈值规则只使用 `good` 数据。
- `device_at`：设备侧测量时间，统一转换为 UTC naive datetime 存储。
- `received_at`：MES API 接收时间，用于在线判断和状态超时保护。
- `source_message_id`：消息ID+点位序号，用于读数记录唯一性。

## 索引与保留建议

V3 为 `(machine_id, point_name, device_at)` 增加复合索引以支持 OEE 窗口查询。设备高频点位上线后，应按点位采样频率制定保留策略：热数据在线保留、历史数据按月归档、报警和状态周期按审计/质量要求留存。清理前必须经业务批准、备份并验证数据归档完整性。

## 边缘 Outbox（本地 SQLite）

`edge_outbox` 保存在网关持久卷 `/data/edge-outbox.db`，字段包括本地递增 `id`、唯一 `message_id`、完整 `payload`、`created_at`、`attempts`、`last_error`。API 返回成功后才删除队列项；网络/服务异常时保留原消息并按插入顺序重试。应监控队列数量及最老消息时间，并为网关磁盘启用加密和容量告警。
