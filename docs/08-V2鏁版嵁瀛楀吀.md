# V2.0 数据字典

## 1. 核心业务实体

| 表 | 主键 | 关键字段 | 约束/说明 |
|---|---|---|---|
| `employees` | `id` | employee_code, full_name, department, skill_level, active | employee_code唯一；技能等级当前为自由编码 |
| `products` | `id` | product_code, product_name, drawing_revision, material_code, active | product_code唯一；当前一条产品主数据记录维护一个当前图纸版本 |
| `routing_operations` | `id` | product_code, revision, sequence, operation_code, work_center, standard_cycle_seconds, setup_minutes, preferred_machine_code | product_code+revision+sequence唯一；旧路线步骤软停用 |
| `nonconformances` | `id` | ncr_no, work_order_id, operation_id, defect_code, affected_qty, disposition, owner_code, status | ncr_no唯一；工单与工序引用V1表 |
| `schedule_plans` | `id` | plan_no, work_order_id, machine_id, start_at, end_at, planned_minutes, status, approved_by | plan_no唯一；设备时间窗建立索引；草案审批时检查冲突 |
| `device_readings` | `id` | machine_id, point_name, numeric_value, text_value, quality, device_at, received_at, source, source_message_id | machine_id+point_name+received_at复合索引；source_message_id全局唯一、可空 |
| `users` | `id` | username, password_hash, role, active | username唯一；密码为PBKDF2-SHA256摘要，不存储明文 |
| `audit_logs` | `id` | username, action, entity_type, entity_id, detail, created_at | 业务操作审计；不是高频设备遥测表 |

## 2. 主要关系

- `nonconformances.work_order_id` -> `work_orders.id`。
- `nonconformances.operation_id` -> `operations.id`（允许为空）。
- `schedule_plans.work_order_id` -> `work_orders.id`；`machine_id` -> `machines.id`。
- `device_readings.machine_id` -> `machines.id`。
- `routing_operations.product_code` 对应 `products.product_code`，当前通过业务逻辑验证，不是数据库外键，以便兼容ERP产品主数据导入。
- `production_reports.employee_code` 当前沿用V1自由文本字段，未建立 employees 外键；上线前应迁移为员工主键并核验历史数据。

## 3. 数据治理要求

1. 工单开工时应冻结产品图纸版本和工艺路线版本，形成工单级工艺快照。
2. 质量数据应关联缺陷代码、检验规范版本、量具编号、检验员和处置批准人。
3. 设备点位应维护统一的机床、控制器、点位、单位、精度和采样周期字典。
4. 高频设备数据应按时间窗口分区或归档，制定保留策略；当前实现仅提供基础 PostgreSQL 表和索引。
5. 审计日志应配置不可篡改归档、访问控制、时间同步、保留周期和备份。
6. 员工技能等级应建立技能矩阵、授权工序/设备范围和有效期，不能仅凭文本等级自动放行。
