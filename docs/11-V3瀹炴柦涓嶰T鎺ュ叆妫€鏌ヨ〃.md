# V3.0 实施与 OT 接入检查表

## 阶段 A：纯软件验证

- [ ] 复制 `.env.example` 为 `.env`，分别生成数据库、用户 Token、边缘网关三组强随机密钥。
- [ ] 确认 API、前端、PostgreSQL 健康检查通过。
- [ ] 创建至少一台设备主数据，设备编码与边缘配置完全一致。
- [ ] 先用 `adapter: mock` 启动网关，观察心跳、采集、状态变化和点位历史。
- [ ] 创建主轴负载阈值规则，验证报警创建、冷却、确认和关闭。
- [ ] 累计计数器分别验证上升、保持、复位场景；确认换班边界口径。
- [ ] 对 OEE 的开始/结束时间、planned_stop、maintenance、running 交叉检查。

## 阶段 B：OT 安全评审

- [ ] 设备厂商确认控制器支持的 OPC UA/MTConnect 能力和许可条件。
- [ ] 设备/控制器/Agent 固件版本及数据字典已登记。
- [ ] OPC UA 使用专用只读身份；禁止写入权限、方法调用和控制对象暴露。
- [ ] OT 与 IT VLAN 分区，防火墙只放行边缘采集所需目标与端口。
- [ ] 边缘网关主动出站访问 MES API；不开放从 MES 到控制器的入站通道。
- [ ] 生产环境启用 TLS、证书校验、日志留存和时间同步（NTP）。
- [ ] 验证 SQLite Outbox 在 API 断网、API 重启、网关容器重启后的消息留存和顺序补传。
- [ ] 评估断网缓存、补传顺序、重复消息、时钟漂移、数据质量码和缓存容量；设置 Outbox 堆积和磁盘容量告警。
- [ ] 明确应急停机、网络隔离和撤销网关密钥流程。

## 阶段 C：单机试点与验收

- [ ] 选择一台非关键 CNC 试点，先采集状态和低风险只读点位。
- [ ] 与控制器 HMI 对照验证状态、主轴负载、转速和计数器准确性。
- [ ] 运行至少一个完整班次，核对 OEE 与人工记录。
- [ ] 验证采集中断、设备掉线、边缘进程重启、API 重启和 PostgreSQL 重启。
- [ ] 验证报警阈值、误报率、确认责任人和响应流程。
- [ ] 经设备、生产、质量、IT/OT 安全负责人共同签字后才扩展到其他机床。

## 不纳入本版本

- CNC/PLC 写入、程序上下载、机床启停/复位、刀补修改。
- 未经验证的自动停机或自动工艺参数调整。
- 使用模拟数据直接计算正式绩效或薪酬。
