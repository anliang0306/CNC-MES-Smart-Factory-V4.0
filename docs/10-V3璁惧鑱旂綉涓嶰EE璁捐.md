# V3.0 设备联网、边缘网关与 OEE 设计

## 1. 目标和边界

V3.0 增加私有网络边缘网关、OPC UA 与 MTConnect 只读采集适配器、设备状态标准化、点位时序入库、设备报警规则、OEE 计算和监控接口。默认启用模拟数据源，便于没有接机床时开展 API 和 UI 测试。

**安全边界：**所有适配器仅执行读取。代码中不实现 CNC 程序传输、PLC 写点、启停机、复位、倍率修改、刀补修改或远程运动控制。真实 OT 接入必须经工厂授权、网络分区评审和厂商确认。

## 2. 数据流

```text
CNC Controller / MTConnect Agent / OPC UA Server
                    |
            OT VLAN / Firewall
                    |
        CNC MES Edge Gateway (read-only)
          | Mock / OPC UA / MTConnect
          | normalize / timestamp / message_id
          v
       HTTPS or private HTTP + X-Edge-Token
                    |
           MES API /api/v3/edge
                    |
       EdgeMessage + DeviceReading + StatePeriod
                    |
       Alarm Engine / OEE Engine / MES UI
```

生产部署建议让 Edge Gateway 主动向 MES API 发起连接，不允许 MES 应用反向访问 CNC 控制器。生产环境建议 HTTPS、证书轮换、OT/IT 防火墙白名单以及专用只读 OPC UA 用户。

## 3. 标准点位命名

| 标准点位 | 类型 | 用途 |
|---|---|---|
| `machine_state` / `state` | text | 设备状态；状态值归一化为 running/idle/setup/alarm/maintenance/planned_stop/offline |
| `spindle_load_pct` | number | 主轴负载百分比 |
| `spindle_speed_rpm` | number | 主轴转速 |
| `cycle_time_seconds` | number | 实际加工周期秒数 |
| `ideal_cycle_seconds` | number | 理想节拍，用于性能效率 |
| `good_count_total` | counter | 累计合格件数 |
| `reject_count_total` | counter | 累计不合格件数 |

点位映射需依据具体机床品牌、控制器版本、MTConnect Agent Probe 和 OPC UA Namespace/NodeId 经现场确认，不可直接照抄示例 NodeId。

## 4. OEE 口径

- 时间开动率 A = 运行时间 / 计划生产时间。
- 性能效率 P = 理想节拍 × 总产量 / 运行时间。
- 质量合格率 Q = 合格产量 / 总产量。
- OEE = A × min(P, 100%) × Q。

`planned_stop` 与 `maintenance` 状态从计划生产时间分母中扣除。无结束时间的当前状态段最多延续到最后一条有效设备数据的接收时间 + 90 秒，避免断网后无限延长运行时间。性能原始值在接口中保留，便于发现节拍/计数器配置问题；OEE 计算时对性能效率按 100% 封顶。产量使用累计计数器在查询窗口内的增量，因此计数器复位、换班清零、控制器断电、计数器位宽回绕需要进一步做设备适配和现场验证。

若缺少状态历史、产量计数器或理想节拍，API 会返回 `data_complete=false`。该标志只代表采集字段齐备，并不代表班次口径已经校准；目前 `shift_calendar_applied=false`，查询窗口中未被标记为计划停机/维护的时间默认视为计划生产时间。因此正式 OEE KPI 上线前还必须实现班次、休息、节假日和计划生产窗口配置。

## 5. 报警规则

支持点位阈值规则：`>`, `>=`, `<`, `<=`, `==`, `!=`；严重程度 low/medium/high/critical；设备编码可空（空表示全设备）；支持冷却秒数。规则触发会创建 AlarmEvent；人员确认、关闭时写入 V2 审计日志。冷却机制用于避免持续高值产生海量事件；具体阈值必须由设备工程师/工艺负责人确认。

## 6. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v3/edge/ingest` | 边缘消息入站，使用 `X-Edge-Token` |
| POST | `/api/v3/edge/heartbeat` | 网关心跳，使用 `X-Edge-Token` |
| GET | `/api/v3/edge/gateways` | 网关状态（登录后） |
| GET | `/api/v3/monitor/overview` | 设备在线状态、状态、报警总览 |
| GET | `/api/v3/monitor/machines/{id}/readings` | 设备历史读数 |
| GET | `/api/v3/oee/machines/{id}` | 设备 OEE，默认最近8小时 |
| GET/POST | `/api/v3/alarms/rules` | 报警规则查询/新增 |
| GET | `/api/v3/alarms/events` | 报警事件查询 |
| POST | `/api/v3/alarms/events/{id}/acknowledge` | 报警确认 |
| POST | `/api/v3/alarms/events/{id}/resolve` | 报警关闭 |

## 7. 边缘网关配置

复制 `edge_gateway/config.example.yaml` 为 `edge_gateway/config.yaml`。模拟采集无需机床连接；OPC UA 配置 `adapter: opcua`, `endpoint`, `node_map`; MTConnect 配置 `adapter: mtconnect`, `endpoint`, `data_items`, 可选 `state_data_item_id`。

网关使用与 API 相同的 `EDGE_INGEST_TOKEN`。采集事件先写入本机 SQLite Outbox，只有 API 返回成功后才删除队列记录；API 中断时保留原始消息和 message_id，恢复后顺序补传。Docker Compose 将 Outbox 放入独立命名卷 `edgeoutbox`。不得把密钥写进 YAML、Git 仓库或工单截图。真实环境应使用秘密管理系统与轮换流程。
